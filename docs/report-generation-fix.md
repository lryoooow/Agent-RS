# 报告生成修复

## 根因

报告 runner 从请求上下文读取会话 ID；AutoGen 聊天入口只传递了用户身份，没有绑定持久化层确认的会话 ID，导致报告在查数据库前就返回 `no_conversation`。旧 runner 注释仍指向已移除的 runtime.plan。

按钮入口另有两个问题：前端把报告结果设为 system 消息，聊天组件因此不渲染下载卡；HTTP 报告端点没有保存报告消息，重新打开历史会话会丢失下载入口。

## 修复

- AIService 对普通和流式执行都绑定服务器持久化层确认的会话 ID，包含新建/替换失效会话；关闭流、异常和并发场景均维护上下文隔离。
- 工具任务登记保存该会话 ID，重启恢复时可以重建上下文。
- 报告合并数据库中的分析记录与本轮成功工具产生的结构化结果，支持同一轮先分析再出报告。HTTP 请求不能提交这批内部数据；会话归属校验始终先执行。
- 只选择可呈现的分析类型，预览、旧报告不会生成空报告或改变目标影像；混合影像的 geo/tool 数据分别选择。
- 按钮结果显示为助手报告卡片，并由报告 API 保存，历史会话可恢复下载入口。
- Word 区分原始影像尺寸与分析网格尺寸；按结果记录中的 area_m2 展示面积，区分建筑提取与全类别统计。
- Word 升级为综合分析报告：加入摘要、影像与分析范围、执行覆盖矩阵、逐项方法与结果、综合分析、成果清单、质量边界和数据来源。
- 自动嵌入平台保存的原始影像预览及每项分析结果图；只读取当前影像成果目录中的 PNG/JPEG，避免外部地址和路径越界。
- 报告支持 SAM3 实例分割、目标检测、光谱指数、水体、云影、波段组合、OCR、裁剪重投影和影像质检；历史 U-Net 结果只作为既有记录兼容读取，不再作为新任务入口。

## 验证

新增 `backend/tests/ai/test_report_context.py` 覆盖会话传递、子任务继承、流关闭、异常、并发、同轮分析、空报告过滤及归属校验。报告/API/聊天/工具相关回归 47 项通过，独立 PostgreSQL 测试库 6 项通过，工具任务恢复测试 16 项通过。前端原有 76 项测试及类型检查、构建通过。

按钮报告只渲染已有结果，不调用模型；保存消息时明确记录输入/输出 token 数均为 0，满足数据库非空约束。新增真实 PostgreSQL 的端点回归同时校验文件、消息、下载元数据与这两个字段，避免仅 mock 保存接口遗漏约束问题。

浏览器脚本 `Agent-frontend/tests/browser/report_generation.py` 使用生产资源与隔离的 API 回放，验证按钮携带正确会话/影像、下载卡、DOCX 下载字节、历史恢复及 SSE 报告卡。运行方式：

```text
python Agent-frontend/tests/browser/report_generation.py http://127.0.0.1:5173 /tmp/report-ui /path/to/valid-report.docx
```

真实 AutoGen 工具链验证使用确定的模型工具调用回放，报告 builder 读取实际数据库分析记录并生成真实 Word；此验证不代表外部模型鉴权状态。生产报告 HTTP 接口及下载另行实测。
