# 影像、图层与对话交互审查（2026-09-15）

## 根因与修复

1. 两处场景导入入口只更新提示文字，没有更新聊天当前影像。增加明确的当前影像选择器，上传、卡片导入、搜索面板导入、Agent 导入及历史选择使用同一个状态；后端验证所有权并持久化选择。对“这张／当前／提取”等单影像请求，框架绑定当前资源，显式 ID、多影像比较和历史指代优先。
2. 图层数组排序与 MapLibre 绘制顺序相反；已有 image source 未更新 URL/坐标，显隐切换也没有修复层序。统一从底向顶排序并同步更新图源、重排图层，框选/标注始终在栅格之上。不同结果文件保留为独立图层，右侧面板从顶向底显示。
3. 上传预览仍按“四波段就是 3/2/1”处理，且丢失 Alpha。上传和场景导入统一采用源文件的波段角色与透明度；uint8 RGB 不再次拉伸。无地理坐标查看器只展示当前影像，避免选区作用于另一张图。
4. 文档清单无条件注入，向量检索只取 top-k，没有相关性门槛。增加任务触发判断、语义相似度下限（默认 0.55），仅对合格文档块扩展上下文与知识图谱；落实 6000 字符预算并合并同轮并行的重复检索。明确已分块文档无需每轮重新解析。
5. Radix 滚动区域内部的 table 布局放大消息的最小宽度，聊天卡片又仅占 85%。改用可收缩的原生滚动容器；表格按宽度换行，长路径/代码可换行，图片不超过消息宽度；输入框随内容调整高度。用户向上阅读时停止跟随滚动。修复中文输入法回车误发送。
6. 框选与影像不相交时仍进入推理流程。增加可见提示与服务端前置拒绝，不消耗 GPU 推理配额，也不建议盲目换轮重试。
7. 场景导入以整景尺寸决定裁剪降采样率，并将各波段的交集拉伸到整个请求范围。改为按选区尺寸确定网格，以 WarpedVRT 按同一个 CRS/变换对齐不同波段，并标记缺失覆盖为 NoData。
8. 增加传感器标称分辨率、已导入合成网格、分析网格的区分。4256dea5c68b 实测为 3916×3999，像元约 57.694×57.697 米；不能按原生 30 米解释。
9. 平台已用 SAM3 开放词汇实例分割替换旧地物分类模型，并采用可配置的保守限制：分析网格超过 5 米/像元则不执行精细目标分割。这是使用规则，不能作为精度保证；用户概念、实例数量、轮廓和面积仍须结合原始影像核查。
10. 修复取消旧会话后旧响应写入新会话、切换账号残留当前影像、报告完成改变当前影像等状态问题。
11. 在当前选中影像的前提检查失败后，本轮从模型可用工具中移除该分析工具，避免反复提交相同无效任务。成功导入覆盖区域的新影像后再恢复。
12. 实测当地 Esri 第 19 级底图返回灰色占位瓦片，第 18 级可用。设置底图最高瓦片级别为 18，更近视图放大已有瓦片；上传影像和分析结果仍可继续放大。

## 验证与依据

- 上传对话中的旧影像 fec6252c9325 与框选范围不相交，新场景 4256dea5c68b 覆盖该范围；真实日志显示导入之后仍调用旧 ID。
- 本地 BGE-M3 对照：建筑提取请求与已上传实施方案相似度最高约 0.444；实施方案架构问题约 0.716；文档与图谱问题约 0.608。0.55 门槛是当前语料上的工程设置，并非通用准确率保证。
- 回归覆盖当前影像绑定/历史恢复/旧请求迟到、图源更新与显隐层序、ROI 判定、RGBA 预览、跨分辨率波段对齐、文档检索门控与图谱过滤。
- [MapLibre ImageSource API](https://maplibre.org/maplibre-gl-js/docs/API/classes/ImageSource/) 支持更新图源 URL 与角点。
- SAM3 服务通过回环地址提供推理，平台将实例掩膜恢复为空间栅格与 GeoJSON，并保留置信度和实例编号。
